# Browser composition contract

The leased process answers `application.open` over the existing extension
channel. Every registered HTTP, fallback and upgrade handler checks the private
forwarder's key before giving the request to the original DSH server.
The market shell is a local operator application. Better Sidebar follows the
native Session cwd for relative files and can open explicit host paths as the
operator. A Session selects its default directory. Only the native browser
device issued to the local operator can enter this shell or run its package
operations.
An upgraded socket carries its authorized Session through subsequent data
events. Its underlying TCP resource predates the HTTP request context.
The original client connection and module services own their endpoint and
manifest semantics. RSI owns browser authentication at the outer listener.
The original Typert session list reads the native visible catalog through
the active HTTP or mux request. Native pages are collected into the bounded
DSH list response. An unavailable page or an overflow rejects the read;
only a successful empty catalog is an empty list.

The market workbench uses one application-level DSH Web shell and slot tree.
RSI and original-brand entry documents share the shell, the application's
Cordis tool registry and a native Session ingress for authorized sidebar
requests. Session-scoped resources hang from that root; they
do not create additional market or sidebar instances. Client modules resolve
the primary brand from the RSI artwork. At `/document/?brand=original` the
same module delegates to the release's original brand factory and slots.
Publishing the same brand again preserves the installed client file and its
timestamps. DSH uses its size and timestamps to version the startup script
that contains the brand module.
The two variants use the same plugin profile. Other modules resolve
from the selected runtime graph and the enabled packages' public client exports.
Use the plugin's own routes for lazy resources; an install-only action does not
mount those routes. The fixed-cohort workbench described below is a separate
Agent reference document for the Todo and Plan integrations.

The optional DSH application shares RSI's React object and workbench. Each
document has one pinned cohort containing react, react/jsx-runtime, react-dom,
react-dom/client, @deepseek-ai/cordis, zod, @tanstack/react-virtual,
@deepseek-ai/dsh-client-store, @deepseek-ai/dsh-client-ui-slots,
@deepseek-ai/dsh-client-ui-primitives and @deepseek-ai/dsh-client-ui-dockkit.
Original UI bundles resolve their synchronous host modules from this table.

The bridge supplies the sessions, remote, remote.commands, remote.session,
locale, uiConversation, resources, sidebarRight and sidebarRightTabs contracts
actually consumed by Todo and Plan, including the pinned common dictionary for Markdown toolbar labels. Package injection metadata does not substitute
for checking these service contracts. RSI's older vendored visual helpers are
not the original runtime.

Composer accessories, transcript renderers and turn tails are generic React
contributions. A renderer definition can have many occurrences; each occurrence
owns its Session, Turn, block, generation and action binding. It is not a root
mount slot and does not consume the existing 16 document-slot budget. Unmount,
Session change and connection retirement invalidate actions.

The selected trusted extension document allows inline style elements and style
attributes, including Shiki output in the original Plan preview. It retains
external script and same-origin resource rules. This is document-wide trust,
not isolation of plugins. A sandboxed iframe cannot share this React context.
Changing the module cohort or policy requires an application restart. The
default RSI document keeps its existing CSP and Rust Markdown ownership; only
the optional original Plan preview uses the upstream JavaScript Markdown path.

Each workbench Session occurrence owns a Cordis scope, a real upstream conversation
assembler and its current resource read. The browser reads canonical journal heads
and content-addressed segments through the ordinary finite Session resource port.
The initial window is bounded to 16 segments (4 MiB); older plan reads page backwards
against their captured head. A missing packed tail rejects the read and requires
refreshing the head, rather than silently mixing histories. Closing the occurrence
retires subscriptions and fences commands and late reads. No browser action writes
the journal or reconstructs a Tool result from display text.

Inspecting a pending native Plan question mounts the original review opener with
the exact question Markdown and a scope-local upstream store. It opens a temporary
preview while the Tool transaction is pending. After settlement, the turn card
opens the recorded call through the original history resource provider. Opening
or dismissing a preview never answers the review.

The browser package ships generated ESM entries for the original conversation
assembler, Chat node registration, English dictionaries and theme presenter.
Run `node scripts/build-browser-support.mjs <dsh-source>` from the plugin repository
to rebuild these entries directly from the selected DSH source.
Shared imports use the document's existing host modules. Each generated entry
identifies its source revision when available and ships with the upstream license.
The package and document receipts identify the shipped bytes. Todo, Plan and
Theme client scripts retain their original packed bytes.
